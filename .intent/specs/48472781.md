## Intent

Allow users to set a custom repetition interval for recurring invoices — for example "every 3 months" or "every 5 weeks" — instead of being limited to "every 1 [day/week/month/year]".

---

## Summary

Today, recurring invoices always repeat with a fixed step of 1 unit: every day, every week, every month, or every year. Users cannot express intervals like every 2 weeks, every 3 months, or every 6 months (quarterly / semi-annual billing).

This feature adds an **interval number** to the recurrence schedule. Combined with the existing recurrence type (daily / weekly / monthly / yearly), users can now define any regular cadence with a single setup.

---

## How It Works

### Setting the Interval

When creating or editing a recurring invoice, the schedule section gains a new numeric input field **"Repeat every"** placed directly before the recurrence type selector. The full control reads naturally:

> **Repeat every** `[ 3 ]` **Months**

- The field accepts whole numbers ≥ 1.
- The default value is **1**, which preserves the current behaviour for existing and new invoices.
- The field is always visible whenever a recurrence type is selected.
- All four recurrence types support the interval: daily, weekly, monthly, and yearly.

### Effect on the Schedule

With an interval of N, the system fires the invoice every N units of the selected type:

| Recurrence type | Interval 1 (current) | Interval 3 example |
|---|---|---|
| Daily | Every day | Every 3 days |
| Weekly | Every week on chosen weekday(s) | Every 3 weeks on chosen weekday(s) |
| Monthly | Every month on chosen day(s) | Every 3 months on chosen day(s) |
| Yearly | Every year in chosen month(s) | Every 3 years in chosen month(s) |

The "days" selection (weekday, day of month, or month of year) works exactly as it does today — the interval only changes *how many units pass between each run*, not *which day within that unit*.

### Frequency Display

Everywhere the schedule is displayed (invoice list, invoice detail view, the upcoming occurrences preview), the frequency label updates to reflect the interval:

- **Interval 1:** "Every Monday" / "Every 1st of the month"
- **Interval 2:** "Every 2 weeks on Monday" / "Every 2 months on the 1st"
- **Interval 3:** "Every 3 months on the 1st"

### End-Date and Occurrence Calculations

When the end condition is set to "After X occurrences" or "On a specific date", the existing end-date calculation is updated to account for the interval. For example, a monthly schedule with interval 3 and 4 occurrences ends 12 months after start (3 months × 4 runs), not 4 months.

### Upcoming Occurrences Preview

The preview list shown when viewing a recurring invoice already exists and continues to work — it will simply show dates spaced N units apart instead of 1.

### Backward Compatibility

All existing recurring invoices implicitly use interval = 1 and are not affected. No user action is required for existing schedules.

## Included / Not Included

**Included:**
- Interval input field in the recurring schedule form (create and edit)
- Interval stored and persisted per recurring invoice schedule
- Correct date calculation for all four recurrence types with any positive integer interval
- Updated frequency label throughout the UI
- Correct end-date and "after N occurrences" calculations with the interval factored in
- Default interval of 1 (backward-compatible)

**Not Included:**
- Non-uniform intervals (e.g. "1st and 15th of every other month" — that remains a multi-day selection within a single interval)
- Fractional or sub-unit intervals (e.g. "every 1.5 months")
- Bulk migration tool to change intervals on existing invoices
- A dedicated "quarterly" or "semi-annual" shortcut button (use interval 3 / 6 with Monthly)
